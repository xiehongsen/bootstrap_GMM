# Bootstrap GMM Analysis of Geochronologic Age Distributions

This repository contains a reproducible Python workflow for bootstrap Gaussian mixture modeling (GMM) of geochronologic age distributions.

The workflow was developed to identify and evaluate major age components in compiled zircon U–Pb and Ar-system geochronologic datasets. Gaussian mixture models are fitted using `scikit-learn`, alternative model complexities are evaluated using the Bayesian information criterion (BIC), and bootstrap resampling is used to assess the recurrence and stability of inferred age components.

The workflow consists of a standalone Python analysis script and a configurable Jupyter Notebook. Dataset-specific settings are defined in the notebook and passed to the analysis script through environment variables, allowing the same numerical implementation to be reused for different datasets without modifying the core analysis code.

Parallel bootstrap calculations are performed using multiple worker processes. Low-level numerical libraries are restricted to one thread per worker to avoid nested parallelism and CPU oversubscription.

## 5.7 Bootstrap and GMM settings

The principal computational settings are:

```python
n_bootstrap = 1000
n_jobs = 8
gmm_n_init = 3
```

### `n_bootstrap`

```python
n_bootstrap = 1000
```

Number of bootstrap replicates.

Increasing the number of bootstrap replicates generally improves the stability of estimated component recurrence and uncertainty, but computational time increases approximately proportionally.

A value of 1000 is suitable for routine analysis, whereas larger values may be used for final publication calculations where additional computational stability is desired.

### `n_jobs`

```python
n_jobs = 8
```

Number of parallel worker processes used for the bootstrap calculations.

This value should be selected according to the CPU resources available on the workstation, server, or HPC system.

Users should avoid requesting more worker processes than the CPU resources allocated to the analysis.

### `gmm_n_init`

```python
gmm_n_init = 3
```

Number of independent initializations used for each Gaussian mixture model fit.

Gaussian mixture optimization can converge to different local optima depending on the starting parameters. Multiple initializations reduce sensitivity to initialization, and `scikit-learn` retains the best-fitting solution among the independent runs.

# 8. Control nested parallelism

Bootstrap replicates are parallelized at the Python/joblib level.

However, numerical libraries such as OpenBLAS, MKL, NumExpr, BLIS, and OpenMP may independently create additional computational threads.

If these threads are not restricted, every Python worker may create several additional low-level threads.

For example:

```text
8 Python workers × 8 BLAS threads = 64 computational threads
```

This nested parallelism can result in:

- CPU oversubscription;
- increased memory consumption;
- poor scaling;
- reduced computational efficiency;
- unstable performance on shared servers.

To avoid this problem, each low-level numerical backend is restricted to one thread:

```python
env["OMP_NUM_THREADS"] = "1"
env["MKL_NUM_THREADS"] = "1"
env["OPENBLAS_NUM_THREADS"] = "1"
env["NUMEXPR_NUM_THREADS"] = "1"
env["VECLIB_MAXIMUM_THREADS"] = "1"
env["BLIS_NUM_THREADS"] = "1"
```

Parallelism is therefore controlled primarily by:

```python
n_jobs
```

at the Python/joblib level.

This configuration is particularly useful for bootstrap calculations involving large numbers of independent model fits.

# 13. Computational workflow

The bootstrap GMM analysis follows the general workflow below.

### Step 1 — Read geochronologic data

The analysis reads age data from the specified Excel workbook.

Individual datasets are selected using their `Sample_ID` values.

### Step 2 — Select the datasets

The two age distributions specified by:

```python
sample_a
sample_b
```

are extracted from the input dataset.

### Step 3 — Fit Gaussian mixture models

Gaussian mixture models are fitted to the age distributions using:

```python
sklearn.mixture.GaussianMixture
```

Each Gaussian component represents a modeled age population characterized by parameters including its mean, variance, and relative weight.

### Step 4 — Evaluate model complexity

Alternative Gaussian mixture models containing different numbers of components are evaluated using the Bayesian information criterion (BIC).

The BIC balances improvement in model fit against increasing model complexity and is used to help determine an appropriate number of mixture components.

### Step 5 — Bootstrap resampling

Bootstrap datasets are generated by resampling observations from the original age distribution.

Each bootstrap dataset represents an alternative realization of the observed sample under repeated sampling.

### Step 6 — Refit the GMM

Gaussian mixture models are fitted independently to each bootstrap replicate.

This produces a distribution of modeled component ages and weights across bootstrap iterations.

### Step 7 — Evaluate component recurrence

The bootstrap results are used to evaluate how consistently individual age components are reproduced.

Components that recur frequently across bootstrap replicates are interpreted as more stable features of the observed age distribution.

### Step 8 — Summarize component stability

The workflow summarizes the inferred age components and their bootstrap characteristics.

Depending on the settings of the core analysis script, these outputs may include quantities such as:

- modeled peak age;
- bootstrap recurrence or support;
- component weight;
- bootstrap age range;
- model-selection statistics.

### Step 9 — Export results

Numerical outputs and graphical results are saved to the specified output directory.

# 14. Statistical rationale

Gaussian mixture modeling represents a complex age distribution as a weighted combination of Gaussian components.

Conceptually, the modeled probability distribution can be written as:

```text
p(x) = Σ w_k N(x | μ_k, σ_k²)
```

where:

- `w_k` is the weight of component `k`;
- `μ_k` is its mean age;
- `σ_k²` is its variance;
- `N` represents a Gaussian probability distribution.

The purpose of the analysis is not simply to maximize the number of fitted age peaks. Increasing the number of components will generally improve the likelihood of the model but may also lead to overfitting.

The Bayesian information criterion is therefore used to evaluate the trade-off between model fit and model complexity.

Bootstrap resampling provides an additional assessment of whether modeled age components are stable with respect to sampling variability.

A component that appears in a single fit but is rarely reproduced during bootstrap resampling may be less robust than a component that recurs consistently across many bootstrap replicates.

# 15. Parallel computation

Bootstrap calculations are well suited to parallel processing because individual bootstrap replicates can be evaluated independently.

The workflow therefore distributes bootstrap calculations across multiple workers using Python-based parallel computation.

The number of workers is controlled by:

```python
n_jobs
```

For example:

```python
n_jobs = 8
```

requests eight worker processes.

Because each worker performs numerical calculations internally, low-level numerical libraries are restricted to one thread per worker.

This avoids nested parallelism and generally improves computational efficiency on multicore systems.

# 18. Numerical reproducibility

Small numerical differences may occur among computers or software environments because Gaussian mixture model fitting involves iterative floating-point optimization.

Potential sources of minor numerical differences include:

- operating system;
- Python version;
- NumPy version;
- scikit-learn version;
- BLAS implementation;
- CPU architecture;
- floating-point operation ordering;
- parallel execution.

For final publication calculations, the software environment and analysis parameters should therefore be archived together with the code.
